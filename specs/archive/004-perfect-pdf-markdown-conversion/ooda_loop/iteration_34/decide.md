# OODA Iteration 34 - Decide Phase

## Decision Priority Matrix

Based on the orient phase analysis, prioritize improvements that maximize quality with minimal risk.

## Priority 0: Investigate AlphaEvolve Extraction (High Impact)

**Rationale**: This single document (F1=0.563) drags the average down by ~4%. Fixing it would raise average from 84.8% to ~89%.

**Action**: Create a debug script to understand why precision is so low (0.395).

**Hypothesis**: The gold standard file might be incomplete or malformed, OR we're extracting redundant content (figure captions, references, headers/footers).

## Priority 1: Reduce Header/Footer Content Leakage

**Rationale**: The `arxiv_header` pattern shows 28 instances in AlphaEvolve and 23 in one_tool - these are inflating our output, reducing precision.

**Action**: Enhance the header/footer detection algorithm to filter:

1. arXiv identifiers (e.g., "arXiv:2501.12345v1")
2. Page numbers
3. Running headers (paper title repeated at top)
4. Copyright notices

**Location**: `src/backend/extraction_engine.rs` - add post-processing filter

## Priority 2: Fix CamelCase Word Merging

**Rationale**: 286 camelCase joins in AlphaEvolve suggests text fragments being concatenated without spaces.

**Root Cause**: When text operators have no space between them, we merge them. But if the spacing is implicit (e.g., kerning), we lose the space.

**Action**: Review text grouping logic in `src/backend/text_grouping.rs`:

- Add minimum character spacing threshold before merging
- Check for uppercase after lowercase as a word boundary signal

## Priority 3: Verify Gold Standard Quality

**Rationale**: Before optimizing for a gold standard, ensure it's correct. Some gold files may have been generated by inferior tools.

**Action**: For AlphaEvolve specifically:

1. Use MarkItDown MCP to generate reference
2. Compare our output vs MarkItDown vs gold
3. If gold is wrong, regenerate it
