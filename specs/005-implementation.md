## The process

1. Review the plan to understand the overall phases and steps of the project.
2. Select a phase: Choose the next uncompleted phase from the plan to work on.
3. Break down tasks: For the selected phase, break down the steps into smaller
4. tasks that can be accomplished using the skills in the skills/ directory.
5. Use skills: For each task, identify the appropriate skill(s) to use. Follow the instructions in the skill's SKILL.md file to implement the required functionality.
6. Create new skills if needed: If no existing skill covers a required task, use the skill-creator skill to create a new skill following the patterns and guidelines in skills/skill-creator/references/skill-patterns.md.
7. Test thoroughly: After implementing each component, test it thoroughly to ensure it meets the specifications and works correctly within the overall platform.
8. Document your work: Update the documentation in the implementation_spec/ directory as needed to reflect any changes or new information discovered during implementation.
9. Iterate: Repeat the process for each phase until the entire platform is built and fully functional.
10. Final review: Once all phases are complete, conduct a final review of the entire platform to ensure it meets all requirements and is ready for deployment.
11. Deploy and monitor: Deploy the platform to the target infrastructure and set up monitoring to ensure its ongoing performance and reliability. manageable sub-tasks.
12. Track progress: Keep track of completed tasks and phases in the plan documentation in implementation_exec/ in a specific file called progress_build_stack.md.
13. While working  you need a scratchpad to jot down ideas, code snippets, and notes. Use the implementation_exec_notes/ directory for this purpose. Create files as needed to organize your thoughts and findings. Remember your context is memory limited so keep your notes concise and relevant to your current tasks. Sometimes the control loops of your scaffold required you to summarize or prune old notes to make space for new ones. Do it diligently, but ensure your reference notes are preserved for future use. If you crash or restart, review your notes to regain context quickly.

Follow this process diligently to successfully build the EdgeQuake platform and fulfill your mission.
