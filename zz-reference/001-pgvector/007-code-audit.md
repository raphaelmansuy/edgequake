# Code Audit — pgvector features used by EdgeQuake but not yet documented

> Cross-referenced against [pgvector v0.8.2 source](https://github.com/pgvector/pgvector)
> (cloned at `/tmp/zzref/pgvector` for verification) and the EdgeQuake
> `edgequake-storage` crate.

This file lists facts that exist in **code** (either pgvector upstream or
EdgeQuake adapters) but were under-documented in the other files of this
folder. Each row is the gap; the linked file is where the detail lives.

## 1. Upstream pgvector surface we under-document

| Feature                                                                                                                                                          | Upstream source                                                                                                                                                      | Why it matters                                                                                                                                                        |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vector_dims(v)` introspection function                                                                                                                          | [`sql/vector.sql:46`](https://github.com/pgvector/pgvector/blob/master/sql/vector.sql)                                                                               | EdgeQuake uses it at [`vector.rs:283`](../../../edgequake/crates/edgequake-storage/src/adapters/postgres/vector.rs) to verify the table's vector dimension at runtime |
| `vector_norm(v)`, `l2_normalize(v)`                                                                                                                              | `sql/vector.sql:49, 52`                                                                                                                                              | Required when switching cosine→inner-product or using `<#>` correctly                                                                                                 |
| `subvector(v, start, len)`                                                                                                                                       | `sql/vector.sql:58`                                                                                                                                                  | Cheap dimensionality reduction trick before re-rank                                                                                                                   |
| `binary_quantize(v) → bit` + `<~>` Hamming, `<%>` Jaccard                                                                                                        | `sql/vector.sql:55`, [`vector--0.7.0--…`](https://github.com/pgvector/pgvector#binary-quantization)                                                                  | The full path for 1-bit re-rank pipelines                                                                                                                             |
| Six op-classes: `vector_l2_ops`, `vector_ip_ops`, `vector_cosine_ops`, `vector_l1_ops`, `halfvec_*_ops`, `sparsevec_*_ops`, `bit_hamming_ops`, `bit_jaccard_ops` | `sql/vector--0.4.4--0.5.0.sql` and `--0.7.0`                                                                                                                         | One op-class per distance — index built for cosine cannot serve L2                                                                                                    |
| `hnsw.ef_search` valid range is **1..1000** (default 40)                                                                                                         | [`src/hnsw.h:52-54`](https://github.com/pgvector/pgvector/blob/master/src/hnsw.h), [`src/hnsw.c:93-95`](https://github.com/pgvector/pgvector/blob/master/src/hnsw.c) | Confirms the cap; do not over-promise above 1000                                                                                                                      |
| `hnsw.max_scan_tuples` default **20000**                                                                                                                         | `src/hnsw.c:102-105`                                                                                                                                                 | Default ceiling for iterative scans before the planner stops                                                                                                          |
| `hnsw.scan_mem_multiplier` is a multiplier of `work_mem` (default 1, range 1..1000)                                                                              | `src/hnsw.c:107-110`                                                                                                                                                 | Memory budget for the iterative-scan candidate set                                                                                                                    |
| `ivfflat.max_probes` default = `IVFFLAT_MAX_LISTS` (32768)                                                                                                       | [`src/ivfflat.c:54-56`](https://github.com/pgvector/pgvector/blob/master/src/ivfflat.c)                                                                              | Effectively "no cap" by default                                                                                                                                       |
| HNSW build constants: `m` ∈ [2,100] default 16; `ef_construction` ∈ [4,1000] default 64                                                                          | `src/hnsw.h:46-51`                                                                                                                                                   | Exact bounds for the WITH clause                                                                                                                                      |
| `vector` index max 2000 dims, `halfvec` max 4000, `bit` max 64000, `sparsevec` max 1000 non-zero                                                                 | [README → HNSW / IVFFlat tables](https://github.com/pgvector/pgvector#hnsw)                                                                                          | The dimension wall that forces halfvec/quantization                                                                                                                   |

## 2. EdgeQuake patterns built on top of pgvector (not in this folder yet)

| Pattern                                                                                            | Where it lives                                                                                                                                                                                                      | Note                                                                                                                |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **`ON CONFLICT (id) DO UPDATE` upsert** for vector rows                                            | [`vector.rs:565-570`](../../../edgequake/crates/edgequake-storage/src/adapters/postgres/vector.rs)                                                                                                                  | `INSERT ... ON CONFLICT (id) DO UPDATE SET embedding = EXCLUDED.embedding, metadata = ...`                          |
| **Dimension introspection from catalog** (`pg_attribute.atttypmod`)                                | [`vector.rs:251`](../../../edgequake/crates/edgequake-storage/src/adapters/postgres/vector.rs)                                                                                                                      | Avoids hard-coding 1536 — derives it from the live schema                                                           |
| **Materialized scalar columns** (`document_id`, `tenant_id`, `workspace_id`) backfilled from JSONB | [`migrations/028_add_vector_materialized_columns.sql`](../../../edgequake/migrations/028_add_vector_materialized_columns.sql)                                                                                       | Three-tier pre-filter (SPEC-007 R-T3-01/04)                                                                         |
| **Partial B-tree indexes** `WHERE col IS NOT NULL` on materialized cols                            | [`migrations/029_add_vector_btree_indexes.sql`](../../../edgequake/migrations/029_add_vector_btree_indexes.sql), [`vector.rs:166-173`](../../../edgequake/crates/edgequake-storage/src/adapters/postgres/vector.rs) | Tier-3 filter for tenant/workspace                                                                                  |
| **GIN `jsonb_path_ops` on `metadata`**                                                             | [`migrations/027_add_gin_index_metadata.sql`](../../../edgequake/migrations/027_add_gin_index_metadata.sql), [`vector.rs:145`](../../../edgequake/crates/edgequake-storage/src/adapters/postgres/vector.rs)         | Tier-2 pre-filter via `metadata @> '{...}'`                                                                         |
| **Counter table for O(1) `count()`**                                                               | [`vector.rs:183-188, 714`](../../../edgequake/crates/edgequake-storage/src/adapters/postgres/vector.rs)                                                                                                             | Avoids `SELECT COUNT(*)` table scan on large vectors tables                                                         |
| **Cast literal to `::vector` at bind time**                                                        | [`vector.rs:488-501, 878`](../../../edgequake/crates/edgequake-storage/src/adapters/postgres/vector.rs)                                                                                                             | Required because sqlx binds query embeddings as `TEXT`; without `::vector` the planner cannot use the HNSW op-class |
| **Workspace isolation via table-name prefix** (`eq_{prefix}_vectors`)                              | [`vector.rs:61`](../../../edgequake/crates/edgequake-storage/src/adapters/postgres/vector.rs)                                                                                                                       | Replaces per-row `WHERE workspace_id =` for hot paths                                                               |
| Cosine score expressed as `1 - (embedding <=> $1)`                                                 | `vector.rs:488`                                                                                                                                                                                                     | The `<=>` operator returns cosine *distance*; documenting score = 1 − distance avoids re-deriving it                |

## 3. What pgvector docs to read next if a contributor wants more

- [`README → "Iterative Index Scans"`](https://github.com/pgvector/pgvector#iterative-index-scans) — the only authoritative explanation of `relaxed_order` re-sort with the materialized CTE + `ORDER BY distance + 0` trick.
- [`README → "Filtering"`](https://github.com/pgvector/pgvector#filtering) — partial indexes, `WHERE category_id = 123` indexes, and the cost model behind why ANN+WHERE is hard.
- [`README → "Troubleshooting"`](https://github.com/pgvector/pgvector#troubleshooting) — `maintenance_work_mem`, query did-not-use-index symptoms.
- [`src/hnsw.h`](https://github.com/pgvector/pgvector/blob/master/src/hnsw.h) — single source of truth for default constants.
- [`src/ivfscan.c`](https://github.com/pgvector/pgvector/blob/master/src/ivfscan.c) — IVFFlat iterative-scan loop; clarifies why only `relaxed_order` is supported for IVF.
