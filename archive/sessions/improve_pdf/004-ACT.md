## Changes Made

### 1. Fixed DBSCAN Epsilon (First Principles Fix)

**File:** `lattice.rs`, line ~530

**Problem:** Adaptive epsilon from 10th percentile created 50-132 columns (one per character position)

**Fix:**

```rust
// OLD: Adaptive epsilon from 10th percentile of inter-element distances
let epsilon = distances[p10_idx];

// NEW: Fixed epsilon of 15pt for column detection
let epsilon = 15.0; // Points - wide enough for legitimate column boundaries
```

**Rationale:**

- In prose text, characters are <1pt apart
- Adaptive epsilon becomes tiny (<1pt)
- Every character position becomes separate column
- Fixed 15pt means: text within 15pt horizontally = same column

### 2. Conditional Clustering (First Principles Logic)

**File:** `lattice.rs`, line ~255-280

**Problem:** Clustering was applied even when grid lines were present, causing crossing_ratio rejections

**Fix:**

```rust
// OLD: Always cluster, use if more granular than grid lines
if detected_x.len() > unique_x.len() && detected_x.len() >= 2 {
    unique_x = detected_x;
}

// NEW: Only cluster when NO vertical grid lines
if unique_x.len() < 2 {
    let detected_x = self.detect_columns_by_clustering(text_elements, &bbox);
    if detected_x.len() >= 2 {
        unique_x = detected_x;
    }
}
```

**Rationale:**

- When vertical lines exist: trust them (PDF author explicitly drew boundaries)
- When no vertical lines: infer from text positions (whitespace tables)
- Don't override explicit grid structure with clustering

### What the ACTUAL Problem Is

Looking at generated markdown line 379:

```markdown
| Agentless Training Free 25.20 14.30 16.14 12.28 75.65 19.76 29.88 | 19.30 |
```

This should be:

```markdown
| Agentless | Training Free | 25.20 | 14.30 | 16.14 | 12.28 | 75.65 | 19.76 | 29.88 | 19.30 |
```

**The grid lines ARE correct (10 columns).** But `extract_text_in_rect()` is dumping ALL text in a cell into ONE column, even when that text is positioned at multiple X-coordinates within the cell.

### First Principles Insight

**PDF Structure:**

```
+------------------------------------------------------------------+
| [Agentless]  [Training Free]  [25.20]  [14.30]  ...            |  (one large grid cell)
+------------------------------------------------------------------+
```

Text elements have different X-positions but all fall within ONE lattice cell's bounding box.

**Current behavior:**

```rust
extract_text_in_rect(cell_bbox) →  "Agentless Training Free 25.20 14.30..."
```

**Needed behavior:**


### Why Clustering Didn't Help

We clustered at the TABLE level (before creating cells), but the problem is at the CELL level (after grid is defined).

The grid detection is correct: 3-5 rows x 10 columns.

But text extraction into cells is wrong: not splitting multi-column text within single grid cells.
