### Root Cause Analysis

#### Text Element Coordinates

Added debug logging to ContentParser and discovered:

```
CP-TJ-ELEM: text='ems with a f' font_size=16.0 x=605.4 y=2622.0
CP-TJ-ELEM: text='ocus on '    font_size=16.0 x=673.9 y=2622.0  ← BEYOND page_width!
CP-TJ-ELEM: text='agentic'     font_size=16.0 x=722.4 y=2622.0  ← BEYOND page_width!
```

#### Page Dimensions

- Nominal page_width: 612 points (US Letter)
- Actual max X of content: 766.3 points
- x_margin: 50 points
- Filter cutoff: 612 + 50 = 662 points

#### The Bug

In `extraction_engine.rs`, lines 346-352:

```rust
.filter(|e| {
    e.x >= -x_margin
        && e.x <= page_width + x_margin   // ← DROPS elements at x > 662!
        && e.y >= y_lower_bound
        && e.y <= y_upper_bound
})
```

Text elements at x=673.9 and x=722.4 were being filtered out because they exceeded `page_width + x_margin` (662).

### Why Does Text Extend Beyond Page Width?

The PDF uses CTM (Current Transformation Matrix) transformations that shift the coordinate system. While the nominal page width is 612 points, the CTM transform results in visual coordinates that extend beyond this boundary.

This is a common issue with:

1. PDFs generated by certain tools (Google Slides, Canva, etc.)
2. PDFs with custom page margins
3. PDFs with scaled content
