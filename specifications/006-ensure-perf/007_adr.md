# ADR-006: Resource Safety Architecture

**Spec ID:** `006-ensure-perf`  
**Status:** Proposed  
**Date:** 2026-06-06  
**Deciders:** EdgeQuake engineering  
**Supersedes:** Ad-hoc per-handler limits

---

## Context

Production OOM (exit 137) on large workspaces. Root cause: `get_all_nodes()` /
`get_all_edges()` on API paths despite superficial pagination caps. Limits are
scattered across 6 crates ([003](003_codebase_audit.md)). Pagination without
push-down violates AX-01 ([002](002_first_principles_model.md)).

## Decision

Adopt a **three-layer resource safety architecture**:

### Layer A — `ResourceBudgetConfig` (DRY SSOT)

Single module in `edgequake-core` exporting all caps from [004](004_resource_budget_catalog.md).
`from_env()` with clamps. Logged once at startup.

### Layer B — `GraphScanOps` (ISP + push-down)

New trait for **bounded** graph reads. Deprecate `get_all_*` on request paths.
Postgres implements filtered/paged Cypher. Memory adapter mirrors semantics for LSP.

### Layer C — `ResourceGuard` (SRP admission)

Pre-flight admission before expensive operations:

```text
Request → ResourceGuard::admit(operation, tenant_ctx)
              ├── node_count_fast() > threshold? → 503
              ├── acquire GraphMaterializationSemaphore
              └── proceed to handler
```

## Rejected Alternatives

| Alternative | Why rejected |
|-------------|--------------|
| **A1: Increase container RAM only** | Masks bug; unbounded cost growth |
| **A2: Keep get_all + stream/chunk in Rust** | Still O(n) DB + network; AX-03 |
| **A3: Redis cache full graph** | Memory moves, doesn't solve; stale data |
| **A4: Hard kill at N nodes in DB** | Product limit, not engineering fix |
| **A5: Pagination in handler only** | Current broken state (V-006-001) |

## Consequences

### Positive

- OOM class eliminated on list/delete/lineage paths
- One place to tune production ([009](009_operator_runbook.md))
- CI can grep-enforce no new `get_all_*` in API
- Delete + lineage share `DocumentGraphCascade` (DRY)

### Negative

- Postgres Cypher complexity for filtered list
- Migration touches 15+ handlers (phased in [006](006_architecture_remediation.md))
- `get_all_*` remains for tests/benches during transition

### Neutral

- Requires index on `source_ids` / tenant+workspace properties (may need migration)
