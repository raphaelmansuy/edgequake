# CRITICAL BUG: Pdfium Backend Returns 0 Pages for All PDFs

**Date:** 2026-01-01  
**Severity:** BLOCKER  
**Component:** edgequake-pdf / pdfium backend  
**Status:** ACTIVE INVESTIGATION

## Executive Summary

The `edgequake-pdf` crate's Pdfium backend is completely non-functional. The `FPDF_GetPageCount()` C API function returns 0 pages for ALL PDF documents, including:

- Valid PDFs confirmed by `file` command
- PDFs generated by reportlab
- Downloaded test PDFs
- Existing test suite PDFs

This breaks 100% of PDF processing functionality.

## Impact

- ❌ **6/10 integration tests FAILING**
- ❌ **All CLI convert operations produce empty output**
- ❌ **All get_info operations report 0 pages**
- ❌ **Cannot extract any text, images, or metadata from PDFs**

## Reproduction Steps

```bash
cd edgequake/crates/edgequake-pdf

# 1. Check PDF is valid
file test-data/sample.pdf
# Output: PDF document, version 1.7, 1 pages ✅

# 2. Try to get PDF info
cargo run --release --bin edgequake-pdf -- info -i test-data/sample.pdf
# Output: Pages: 0 ❌

# 3. Try to convert
cargo run --release --bin edgequake-pdf -- convert -i test-data/sample.pdf -o output.md
# Output: ✅ Converted... 0 characters extracted ❌

# 4. Run integration tests
cargo test --release test_get_pdf_info
# Output: FAILED: assertion `info.page_count >= 1` failed ❌
```

## Technical Analysis

### Code Path

```rust
// src/backend/pdfium.rs::extract()
let pdfium_doc = self.pdfium
    .load_pdf_from_byte_vec(pdf_bytes.to_vec(), None)
    .map_err(...)?;  // ✅ Succeeds - no error

let page_count = pdfium_doc.pages().len();  // ❌ Returns 0

// Internally pages().len() calls:
// src/pdf/document/pages.rs in pdfium-render crate:
pub fn len(&self) -> PdfPageIndex {
    self.bindings.FPDF_GetPageCount(self.document_handle) as PdfPageIndex
}
// Returns 0 for all PDFs!
```

## Possible Root Causes

### 1. Pdfium Library Binding Issue ⚠️

- `pdfium-render` crate version: 0.8.x
- Features enabled: `image_024`, `thread_safe`, `pdfium_latest`
- Library path: `libs/lib/libpdfium.dylib` (exists, 5.3MB)
- **Hypothesis:** Bug in pdfium-render 0.8.x or incompatible with current pdfium library

### 2. Pdfium Library Compatibility ⚠️

- Platform: macOS ARM64 (Apple Silicon)
- Pdfium version: Unknown (need to check library version)
- **Hypothesis:** Wrong architecture or corrupted library file

### 3. Document Handle Corruption ⚠️

- `load_pdf_from_byte_vec()` returns a handle
- Handle appears valid (no null check fails)
- But `FPDF_GetPageCount(handle)` returns 0
- **Hypothesis:** Handle is created but document not properly parsed

### 4. Recent Regression 🔍

- Last known working state: Unknown
- Recent refactoring: Backend abstraction added in commit `b4df6a9`
- **Need to:** Git bisect to find when this broke
